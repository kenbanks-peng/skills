# Dispatch input/output inventory (DSP-C766)

## Scope and rules

This inventory covers the consolidated interface, not deleted entry points. The public command is `scripts/dispatch.py`. Its work is argument parsing and routing. The implementations are internal modules under `scripts/dispatch_lib/`. Only `scripts/probes/agent_processes.py` keeps a separate process entry point. It runs inside the selected container.

Normal order: selection → startup → launch → inspect/monitor → report/review → integrate/verify → finish → reconcile → close-run. Resume is a separate command. Recovery and doctor are exceptional paths. [SKILL.md](SKILL.md) and [recovery.md](recovery.md) separate these paths.

Shared contracts for all rows:

- **Arguments:** argv arrays, not shell evaluation. No stdin assignment format. Required inputs fail with command help or a JSON error and next action. Checks are trusted code, not a sandbox.
- **Identity:** full task refs, saved task IDs, canonical Git/common directories, exact worker branch/worktree/handle, exact runtime/container/mount and UI/server identity. Saved evidence never authorizes a replacement identity.
- **Status:** `ok` is the command outcome, not a claim that delivery, cleanup, or the run is complete. Finish exposes delivery, task completion, cleanup, and housekeeping separately.
- **Evidence:** paths are outside worker checkouts. Worker/run records use atomic writes and fsync. Do not copy whole saved records between commands. Read the field or evidence file needed for the next action.
- **Presentation:** default JSON uses explicit selected fields. Strings have bounded previews; lists show counts, at most three entries, and a remainder count. Histories, mounts, receipts, and full logs are not embedded. Evidence paths are not shortened.
- **Retrieval:** use returned record/evidence/source paths. `--verbose` shows complete structured command evidence and expands retained subprocess logs. Do not retry a mutation just to change its output format. Read its evidence instead.
- **Read-only queries:** inspect, finish inspection, integration closure check, and preflight do not save fresh observations or recreate missing locks. Repeat a read-only query with `--verbose` for its full live observation. Historical evidence stays in the saved record. Recovery snapshot can save diagnostic evidence but does not change tasks, workers, or UI.
- **Exit codes:** 0 for the supported operation's successful outcome, 1 for an operation failure, 2 for argparse usage errors. Pending safe cleanup can coexist with successful task completion; it blocks run closure.

## Measurements and budgets

The baseline was taken **after CLI consolidation**, before input/output changes. A real-Git controlled launch produced the fixture [io-baseline.json](tests/fixtures/io-baseline.json). It contains a worker identity, prompt/config references, activation, Workmux observations, and container mounts. This is test data, not a usable worker authorization record.

Measure UTF-8 bytes with `json.dumps(value, indent=2)`. Repeat its saved event list to measure history growth, while leaving current identity/outcome unchanged:

| Saved events | Consolidated baseline output | Compact output |
| ---: | ---: | ---: |
| 1 | 6,962 | 550 |
| 10 | 41,036 | 550 |
| 100 | 381,776 | 550 |

These are controlled measurements, not token estimates or live runtime benchmarks. The one-event reduction is 92%. No baseline includes deleted wrappers. The deterministic test fixes these byte counts.

Budgets in `test_io_contracts.py`:

- Launch summary fixture: 550 bytes, unchanged as history grows.
- Synthetic realistic launch observation with a large log: less than 1,500 bytes at 1, 10, 100, and 1,000 events.
- Selected report summary: less than 1,200 bytes for 1,000 and 100,000 repeated evidence words.
- Lifecycle summaries and large pending-cleanup/error lists: less than 8,192 bytes for tested canonical paths. Path lengths are not truncated to meet a budget.
- Worker input: complete requirements remain unbounded. A 10,000-line description is retained exactly; 1,000 identical decision notes become one body. Projection overhead is less than 350 bytes for that fixture.
- Verification: complete 1,200,000-byte output survives checkout cleanup. Saved records contain a 4,096-byte preview plus full log paths and byte counts. Verbose output restores the full stream.
- Recovery: output over its existing 65,536-byte observation limit still fails closed. The complete excess stream is now retained, not discarded.

## Deliberate exceptions and retention

- Do not trim requirements, authorization text, decisions, acceptance commands, exact identities, dirty-file lists used for cleanup, or error evidence to meet a prompt or storage budget.
- Worker events, run membership, note IDs, and failed-check worktrees can grow on disk. That growth is audit/recovery evidence, not agent context. No automatic evidence garbage collection is introduced.
- Current integration and its journal event remain present in the worker record. Stop observations and exact mount identity can repeat across independently required checks. These are linear, nonrecursive safety evidence; summaries do not expand them.
- Full Aven report sources are content-addressed. Selected report evidence and immutable phase outcomes can repeat a selected note or phase result, but not the full task history. This preserves the reviewed evidence across later Aven changes.
- Read-only inspect does not persist a new observation. Its full current response requires explicit verbose inspection. That is necessary to satisfy the no-mutation contract.
- Paths remain valid after worker cleanup because they point into the common Git directory, not the removed worker. Keep that Git evidence directory for audit and recovery. Do not move or delete it while a run has pending work.
- Recovery/verification process groups do not contain a child that deliberately leaves the group. The repository lock does not exclude unrelated writers that ignore it. Local worker stop proof is still not automatic. No safety claim is added for these cases.

## Test coverage

The existing suites cover routing, real-Git lifecycle behavior, saved identity, locks, status confirmation, prompt quoting, inspection/resume, integration and independent checks, stop, strict archive/removal, durable reporting, pending cleanup, and closure. Imports and consumers now use the consolidated CLI or internal Python modules, not removed public entry points.

`test_io_contracts.py` adds deterministic summary budgets/history-growth checks, input projection with large requirements and duplicate notes, separate resume/help/argument contracts, evidence-write failures, full verbose retrieval, nonrecursive stop receipts, complete large subprocess logs, read-only inspection including wait, compact integration/finish, pending cleanup, and blocked closure. Controlled lifecycle tests prove retained paths work after worker removal. Live host UI/container behavior is not claimed by these tests.
